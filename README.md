# 衡见写作

**把复杂问题讲清楚，把空话改成判断，把建议落到动作。**

面向中文公众号、行业评论、AI 与产品解读、职场观察的个人化写作与改稿 Skill。
</div>

---

## 为什么做这个 Skill

很多文章不缺信息，缺的是清晰的推进。

观点有了，段落之间却接不上；资料很多，真正支撑结论的证据却很少；标题看起来有冲突，正文却没有回答标题提出的问题；结尾列了一串能力，读者看完仍然不知道下一步该做什么。

「衡见写作」来自真实的多轮改稿过程。它不追求堆金句、套模板或把文章写得像短视频口播稿，而是帮助作者守住原有主旨，在有限篇幅内把逻辑、证据、表达和行动建议同时做实。

> 好文章不是把每一段都写得用力，而是在关键位置给出准确判断。

## 它能做什么

- 根据材料完成公众号文章、行业评论和职场观察
- 在不改变主旨与骨架的前提下重写全文
- 通过多轮 Battle 逐段定位问题、解释原因并修改
- 压缩废话、补足逻辑承接，控制文章节奏
- 设计标题、头图标题、副标题和引言
- 把抽象建议改成可以执行的能力清单
- 核验概念、数据、人物身份、产品能力和引用来源
- 输出正常文本、Markdown 或公众号复制版

## 写作原则

### 守住主旨

用户已经确认的主题、骨架、受众和说话位置优先级最高。增加深度时，先替换空话和重复解释，不靠增加篇幅解决问题。

### 判断有据

事实写到证据允许的位置。相关性不写成因果，局部任务表现不概括成全面超越，理论概念不缩成方便文章使用的口号。

### 推进自然

后一部分回答读者读完前一部分后自然产生的问题。钩子只放在关键转折处，金句只负责钉住核心判断。

### 建议具体

少写“提升综合能力”，多写“提出关键问题、补充有效上下文、质疑 AI 结论、核验事实与来源”。能力名称后面必须跟着动作、对象或检查标准。

### 保持人味

用自然中文讲清事实和判断，避免商业汇报腔、模型黑话、机械排比和无依据的宏大结论。站在熟悉行业的从业者角度，但不虚构亲历、职位或内部信息。

## 快速开始

克隆完整仓库：

```bash
git clone https://github.com/HengboLee/hengjian-writing.git
```

将整个目录导入支持 Agent Skills 的客户端。不要只复制 `SKILL.md`，`references/` 中的风格规则和 Battle 流程也是 Skill 的组成部分。

已经安装后，可以直接调用：

```text
@hengjian-writing 根据下面的材料写一篇公众号文章，受众是职场新人。
```

```text
@hengjian-writing 保留原文章的骨架和主旨，压缩废话并补足段落承接。
```

```text
@hengjian-writing 我们来 Battle。先判断第二段为什么突兀，只修改这一处。
```

```text
@hengjian-writing 把定稿转换成能直接复制到微信公众号的版本，不改变正文内容。
```

## 工作方式

1. 锁定受众、作者位置、核心问题、核心判断和目标篇幅
2. 整理材料并核验关键事实、数据与来源
3. 建立从现象到原因、后果、解决方向和具体行动的问题链
4. 设计标题、引言、转折钩子和少量关键判断
5. 完成初稿后检查逻辑、证据、节奏和建议是否对应
6. Battle 阶段一次解决一个主要问题，避免局部修改带偏全文
7. 根据发布场景输出正常文本、Markdown 或公众号复制版

## Battle 改稿

Battle 不是把全文反复推倒重写，而是把分歧说清楚。

每一轮先回答三个问题：

1. 这一处具体哪里有问题
2. 问题来自逻辑、事实、措辞还是节奏
3. 修改后会不会影响前文、后文或标题

只有在用户确认方向，或明确要求“结合以上修改重新出一版”时，才重新输出完整文章。

## 稿件检查

完成长稿后，可以运行：

```bash
python3 scripts/check_hengjian_style.py 你的文章.md
```

脚本用于发现部分高频表达问题，例如不符合风格的标点、句式和空泛措辞。它不能代替人工审稿，也不能代替事实核验。

## 适用边界

这个 Skill 主要服务于中文非虚构写作，不负责用虚构案例证明现实观点，也不会为了制造冲突夸大数据、模型能力或行业变化。

当材料不足以支撑长文时，它会优先建议补充材料、缩小结论或缩短文章，而不是重复解释来填充字数。

## 当前状态

这是一个持续迭代的个人写作 Skill。规则来自真实文章的多轮修改与验证，后续会继续补充经过实践验证的写作方法，而不是收集未经使用的通用提示词。
